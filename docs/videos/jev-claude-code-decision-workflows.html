Jev 與 Claude Code：三種決策型整合位置

📺 Gary Chen⏱ 18:01🗓 2026-10-13🌐 zh-TW🔗 https://youtu.be/_yFen1B8hdU?si=7NI3dU9mm4G8epEt

影片將 Jev 定位為負責快速選擇與判斷的模型，並以 Claude Code 的工作流說明三個整合位置：模型／skill 路由、海量資料分類與打分、以及程式完成後的自動化驗證。核心分工是讓 Jev 處理大量、可枚舉選項的高頻判斷，再把少數高價值或高風險項目交給大型模型深入處理。

01

先建立分工：快速判斷與深度推理各司其職

0:46

影片把 Jev 描述為偏向 System 1 的「直覺反射」，大型模型則負責 System 2 的深度推理。Jev 接收資料、問題與選項後，回傳各選項的機率；它不是用來生成長篇文字或進行長篇推理。

作者的實作起點是取得 API key，把 key 與官方文件交給 Claude，說明要達成的任務，並限制該判斷步驟使用 Jev。也可要求 Claude 將設定封裝為 skill 或開關，方便與原本工作流對照成本與輸出品質。

02

位置一：讓 Jev 先做模型與 skill 路由

2:16

影片指出，不少日常任務不需要一直使用最高階模型，例如找檔案、轉換文字格式、查看函式參數。Jev 可在每次 prompt 送出後先判斷任務所需等級，再把任務交給相應模型。

同樣的選擇也可用於 skill：不必讓所有 skill 名稱與描述一直塞進 context，而由 Jev 從清單中挑出相關 skill，再通知 Claude 精準載入。作者提醒，省 token 後的品質是否足夠仍取決於個人工作內容與容錯率，必須自行測試。

03

位置二：海量、同題型資料的分類與打分

6:19

影片列出留言分類、潛在客戶意向打分、會員流失風險、社羣貼文分流與客服逐字稿歸類等案例。共同模式是讓 Claude 自動調用 Jev 批次判斷，再輸出表格、CSV、Excel 或 dashboard。

作者將底層流程概括為：Jev 先粗篩，Claude 再處理篩出的精華。例如先替大量潛在名單打分，只把高分客戶交給 Claude 做背景研究與客製開發信；影片也把長影片精華挑選視為可讓 Jev 擔任第二雙眼睛的用途。

適用判準是任務量大、每筆資料問的是同一個問題；影片舉例包括發票是否可疑、Email 是否為垃圾信、留言是否違規、退款是否符合資格、會員是否可能退訂。

04

位置三：程式完成後的快速驗證迴圈

10:54

影片將 Code Review 與多輪測試描述為昂貴的 feedback loop，並列出四種用法：用自然語言設定語意型 Linter 規則、掃描整個 codebase 的註解與 code smell、以大量具體問題初篩程式改動，以及以多個瀏覽器 agent 做對抗測試。

流程核心不是把所有審查交給 Jev：它在第一線進行大量快速條件判斷，再把高風險項目交給 Claude 深入審查與修復；若發現偏差，Claude 回頭調整 prompt 規則與門檻。

05

導入順序：先找工作流裡的「選擇題」

15:30

作者總結三個位置共用同一原則：它們是 Claude Code 原本在做判斷、而非生成產出的環節。若答案能事先枚舉成明確選項，該步驟就是 Jev 的適用位置。

影片建議先從模型與 skill 路由開始，因為不需改變既有操作習慣；需要處理大批資料時導入分類與打分；每天寫程式、推 PR 的人則可優先探索自動化驗證。若不確定切入點，可讓 Claude 回看近期對話紀錄，盤點哪些步驟只是分類或篩選。

只要工作流中的某一步本質上是在做選擇與判斷，那一步就是影片所說 Jev 的黃金位置。

  4. 6:19針對大量資料、每筆都問同一問題的情境，Jev 可先批次分類、打分或粗篩，再由 Claude 整理輸出或處理高分項目。
