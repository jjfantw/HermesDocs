本地 AI 的記憶體、模型與設定指南

📺 AI懶人報⏱ 16:00🗓 2026-11-04🌐 zh-TW🔗 https://youtu.be/1nomxygMILI

影片以本地 AI 的記憶體配置為主軸，先說明模型容量、context 與 Mac 統一記憶體的關係，再比較 16GB、32GB、64GB、128GB 可承擔的模型與工作。後續解釋 MoE 為何可能更快，並區分 LM Studio、Ollama、llama.cpp 的定位；最後以實例說明適合與不適合留在本地的工作，以及 context、模型包裝、KV cache、容量餘裕與連線安全五類常見問題。

01

先判斷失敗是不是 context 設定造成

0:14

影片指出，許多人把本地模型接到 agent 後遇到遺忘、失敗，會直接歸因於模型不夠聰明；但設定也可能是原因。影片引述 Ollama 文件：顯示記憶體小於 24GB 時預設 context 為 4,000 token；同時引述 OpenClaw 建議本地 agent 至少要 64,000 token。

context 是模型一次能看到的內容，包含對話、讀取的檔案及 agent 本身的說明。影片舉例，agent 即使只收到一聲「嗨」，其預先載入的內容也可能已佔約 5,000 token。

設定
02

模型容量先用 4-bit 的簡式估算，再留工作空間

1:56

影片提供快速估算法：4-bit 模型約需「參數量 × 0.6GB」記憶體；片中以 9B 約 5.7GB、27B 約 17.6GB、35B 約 22.4GB 的檔案為例。

模型檔案能放入不代表可順暢使用，context 也需要記憶體。Mac 的統一記憶體雖可供 CPU 與顯示晶片共用，但影片建議新手先以總記憶體約四分之三可供模型使用來估算。

容量
03

16GB 到 128GB：升級買到的是不同的工作餘裕

3:14

16GB 適合約 5GB 的小模型，影片列出的用途是改寫、翻譯、文章摘要與表格整理；讓小模型自行規劃多步驟並呼叫工具則容易出錯。24–32GB 是影片稱為甜蜜點的區間：32GB 才較適合舒適地使用 27B 等級模型，並可處理私人文件問答、批次整理或範圍明確的本地 coding agent 工作。

64GB 未必能換到更大的主力模型，但可選擇較少量化版本並開更長 context，適合長文件與較久的 agent 工作。128GB 才能進入影片所稱 100B 以上模型；再往上，影片認為除非資料不能離開本機或需多人共用，否則效益未必划算。

硬體
04

MoE 可更快，但不等於更省記憶體或更穩

6:52

影片用 MoE（專家混合）說明：稠密模型每生成一個 token 都會動用全部參數；MoE 每次只調用部分專家，因此搬運資料較少、生成可能更快。片中以 Qwen3.6 35B-A3B 說明，A3B 表示每次約只動用 30 億參數。

但所有專家仍需在記憶體待命，所以 MoE 不會讓模型整體佔用變小。影片也提醒，社群回報中稠密模型在長 agent 任務可能較穩；選擇時要在速度與穩定性間取捨。

模型架構
05

軟體與檔案格式會改變實際速度

8:13

影片將 LM Studio 定位為有完整介面的模型工具，便於搜尋、下載與聊天；Ollama 適合在背景提供模型服務，讓 OpenClaw、Claude Code 等 agent 工具串接；llama.cpp 則是可手動調整、功能較多的底層引擎。

影片指出，同一台 32GB Mac mini、同一顆 Qwen 27B，僅更換執行軟體與檔案格式，速度就可能從約每秒 8 個 token 變成約 21 個。Mac 使用者在影片中被建議確認 MLX 格式並先更新軟體。

工具
06

本地適合私密與重複任務，困難規劃交給雲端

9:15

影片列出的實例包括：讓本地模型閱讀合約、病歷、財務或客戶文件；把多張發票讀出後整理成試算表；以本地 coding agent 分類銀行交易並製作儀表板；以及為大量影片片段產生描述以便文字搜尋。

影片提出的分工是：雲端模型處理規劃與困難工作，本地模型處理私密、量大或高度重複的工作。

使用情境
07

先知道三種容易失望的使用方式

10:51

影片不建議期待本地 27B 模型在大型專案中直接擔任 coding agent：讀取長 prompt 與整個專案可能很慢。也以社群案例提醒，9B 小模型做 agent 可能產生不可靠結果。

此外，為了塞進小電腦而將模型壓到低於 4-bit，可能先破壞工具呼叫格式；影片建議若要做 agent，盡量維持 4-bit 以上。

限制
08

五個新手坑與影片的安全清單

11:52

五個坑依序是：context 設太短、模型的 chat template 遺失、壓縮 KV cache、只看模型能不能放得下，以及以為本地部署必然安全。影片指出，KV cache 壓縮對聊天影響可能較小，但對 agent 的工具呼叫可能造成問題。

安全上，影片建議 Ollama 維持只聽本機，不要為便利直接對所有網路開放；將 Ollama、LM Studio 更新到最新版；給 agent 工具權限時選擇官方或知名來源模型；工作資料夾不要放密碼或金鑰；LM Studio 若開本地伺服器則開啟驗證。

安全
09

影片的升級判斷

14:25

影片的結論是：16GB 使用者若每天要跑 agent 或希望使用 27B 等級模型，升到 32GB 才明顯有感；32GB 使用者若常讀長文件或讓 agent 長時間工作，64GB 才有意義；想跑 100B 以上模型則要到 128GB。

若不屬於這些情況，影片建議先把軟體與設定調整好，再評估硬體升級。

升級

難的交給雲端；私密的、重複的留在本地。
