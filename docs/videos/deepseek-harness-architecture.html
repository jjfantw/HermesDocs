DeepSeek Harness 框架怎麼設計的？一切皆插件｜架構解析 ｜ 連主迴圈都能換

📺 Jim AI Notebook⏱ 16:08🗓 2026-08-18🌐 zh-Hant🔗 https://www.youtube.com/watch?v=i7ZWtyLzc1Q

這支影片把 DeepSeek Harness 當成一份架構文件來讀：它不是新模型，而是讓模型能呼叫工具、記錄工作、套用權限與沙箱、並在出事時留下可追溯證據的執行環境。影片先把 Harness 比喻成駕馭馬的裝備，說明開放權重如果沒有執行環境，就像有大腦但沒有神經系統。接著比較 Claude Code、Codex、OpenClaw、Hermes 與 Harness 的差異：核心問題不是誰比較強，而是你能改到哪一層。影片的重點是 Harness 站在「連主迴圈都能替換」的層級，透過 Cordis 的插件化、可回收註冊、設定層堆疊與服務命名，讓系統可以被拆、被換、被組合。後半段聚焦工具呼叫與工作記錄：工具執行前先記錄，經過權限與沙箱，執行後還能檢查結果，最後凍結成不可竄改的結果。影片也提醒 Harness 目前是開發者預覽版，內建沙箱不是完整安全邊界，本機介面不代表模型在本機跑，且 agent 成本高度取決於快取命中與尖離峰價格。

01

1. Harness 的重點不是模型，而是執行環境

00:00

影片開場指出，DeepSeek 這次公開的不是模型，而是讓模型真的能動手做事的執行環境。這件事重要，因為它代表模型公司開始在意模型跑在哪裡、被誰管理、出事時由誰喊停。

影片用 Harness 的原意「馬具」作比喻：模型是馬，Harness 是韁繩、馬鞍與腳蹬。這些裝備不會讓馬更快，但沒有它們，人根本無法上馬；同理，權重只是大腦參數，沒有執行環境就不能開資料夾、記錄過程、呼叫工具或在危險時停下。

定位
02

2. 這類 agent 工具真正差在可改到哪一層

01:52

影片先用「解決什麼、什麼時候動、碰得到什麼」比較 Claude Code、Codex、OpenClaw、Hermes 與 Harness。Claude Code / Codex 解決模型碰不到專案的問題；OpenClaw 強調資料在自己裝置上；Hermes 強調會跟著使用者一起長大；Harness 則處理想改系統卻改不動的問題。

接著影片把差異改用房子比喻：第一層像租屋，只能擺家具與掛畫；第二層像買下舊房子，原始碼可改但維護成本也歸你；第三層才是 Harness 的位置，牆本身是一片片可換的，甚至主迴圈本身也是插件。

工具比較
03

3. Cordis 提供的核心是「所有東西都是插件」

04:49

影片說 DeepSeek 沒有從零打造骨架，而是選擇 Cordis 這個做了四年的社群專案。Cordis 想解的是一個軟體工程難題：怎麼讓系統的每一塊都能被替換、疊加、拿掉，同時不弄壞其他部分。

Harness 文件的第一個設計哲學是「所有東西都是插件」。因此模型轉接、工具清單、驅動 AI 做事的主迴圈都不是特權核心；想要微調主迴圈時，不是去改原本的核心，而是寫一個自己的插件掛上去，再把原本那個拿掉。

架構核心
04

4. 可卸載與可倒帶，才是真正的熱插拔

06:40

影片特別解釋，插件註冊上去的東西在插件被移除時必須整個收回。這對應到日常經驗：很多軟體反安裝後仍留下設定、資料夾或背景影響，因為只做了安裝那半邊。

Harness 的規則是每一個註冊都要帶移除方法。你加提示詞、工具或監聽器，都透過同一套機制裝上去，也由同一套機制記住如何還原；插件卸載時，做過的事會照順序倒著收回。影片認為這是熱插拔真正可行的原因。

生命週期
05

5. 設定層與服務命名讓底層實作可替換

07:30

影片說 Harness 跑起來的東西是一疊設定層堆出來的：底層包含模型、轉接、工具、儲存、沙箱、權限；上層可以再疊網頁介面、無介面執行、個人設定檔與臨時參數。

另一個重要設計是服務用固定名字被引用，例如工具叫 Tools、模型叫 LM、工作階段叫 Sessions。其他插件找的是這些名字，而不是某份具體程式碼，因此底層可以換成完全不同實作，上層不必跟著改；啟動順序也能由系統依賴宣告自動計算。

組態與依賴
06

6. 工具呼叫先記錄，再放行，最後凍結結果

09:10

影片把工具呼叫拆成一條比想像更長的路：模型說要跑指令時，第一件事不是執行，而是先把呼叫寫進記錄。這讓系統即使當掉，也查得到當時想做什麼。

接著工具呼叫會經過權限與沙箱決定放行、阻擋或詢問人。影片強調，如果問不到人，例如沒有介面或沒人在電腦前，就算拒絕，不算通過。工具跑完後還有結果檢查，可以擋下、替換或補話，最後才凍結成不可再改的結果。

安全與稽核
07

7. 「模型看得到的，一定被記下來」是整套設計的支點

10:00

影片認為工作階段記錄裡最漂亮的一句是：模型看得到的，一定被記下來。意思是只要某段文字進入送給模型的請求，它就必須能從記錄裡重新拼回來，而且系統會在執行時檢查這件事，做不到就報錯。

這讓許多功能都變成同一條記錄的衍生品：從某一步分岔出去重跑、關掉電腦明天接續、追查 AI 為什麼刪掉檔案，都可以回到當下的完整脈絡。影片把它比成法院逐字記錄，而不是事後補寫的會議紀要。

工作階段記錄
08

8. 能力接縫必須拆出定義、實作與使用者

10:49

影片說能力接縫要有三個角色：定義能力長相的人、真正實作它的人、使用它的人。只有其中一個角色，不算真正的接縫。

影片用檔案系統與跑指令共用同一個執行環境作例子：當執行環境指向遠端沙箱機器，跑指令工具、終端機與程式碼補全會一起搬過去，不需要各自另外改。關鍵是中間的插座形狀被單獨定義出來。

可替換性
09

9. 防禦性模式把真實傷疤寫成規則

12:18

影片介紹另一份文件「防禦性模式」，它不是在講理想設計，而是把真的發生過或差點發生的 bug 寫成規則，防止再犯。

影片挑了兩條：第一，結果可能同時包含多種狀態，例如程式超時又回報成功，所以超時訊號與結束碼要分開呈現，不能互相遮蔽。第二，關閉要等到真的安靜，不是發出停止指令就離開；要等子程式死透，且先關監聽再殺，避免晚回來的通知亂跑。

可靠性
10

10. 四種模式與實際限制：先玩，不要急著正式上線

13:10

影片說安裝後有四種模式：完整版會開檔案、指令、搜尋、規劃與子代理；第二種把工具包成程式碼，讓 AI 用寫程式方式一次呼叫多個工具；第三種極簡，只給指令列與編輯器；第四種是創造者模式，能讓 AI 回頭改正在跑的系統本身，官方標示高度信任，影片建議先不要碰。

影片也列出限制：Harness 目前是開發者預覽版，之後一定會有不相容變更；內建沙箱網路不受限且其他程式看得到，不能當真正安全邊界；本機網頁介面只是控制台，模型仍在遠端，仍需金鑰與費用。

風險提醒
11

11. Agent 的帳單形狀取決於快取與尖離峰

14:37

影片提醒，骨架免費不代表模型免費；agent 工作的成本結構與一般聊天不同，關鍵在快取命中。Agent 一輪一輪跑，每輪都會把前面做過的事重新送入背景，因此很像天天走同一條路的人。

影片引用官方價目表說，同樣一百萬個字，系統存過與沒存過的價格差 31 倍；也提到官方把一天切成尖峰與離峰，尖峰價格是離峰兩倍，而換算到台灣時間剛好落在上班時段。

成本

12. 結論：模型公司開始搶執行環境

15:30

影片最後把整份文件收束成一句話：讓一個很複雜的東西，還能被一個人看懂，還敢動手去改。

如果只記一句，影片建議記「模型看得到的，就一定被記下來」，因為它支撐了倒帶、分岔與查證。對工程師，影片建議可以裝起來玩，但先不要用在正式事情；對看趨勢的人，重點不是框架本身，而是模型公司開始搶執行環境。
