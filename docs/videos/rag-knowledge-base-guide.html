RAG 新手完整教學：從資料整理到錯誤排查

📺 Gary Chen⏱ 21:01🗓 2026-10-28🌐 zh🔗 https://youtu.be/YM-6-QhGHgI

影片以「巴菲特數位分身」為例，說明 RAG 的核心不是把整包資料交給模型，而是先找出與問題相關的少量資料，再讓模型根據這些資料回答。內容依序拆解 R（資料整理與檢索）、A（重排並組成小抄）、G（依小抄生成答案），最後提供從資料、檢索、重排到模型端的排錯順序。

01

RAG 解決的是「資料太多，不能每次全塞給模型」

00:00

影片以巴菲特資料為例：直接把大量文件當附件交給模型，會遇到 context window 上限；即使勉強塞得下，每個新問題仍得重新讀取，因而變慢且成本升高。

RAG 的做法是先找出真正有關的少數段落，再交給 AI 回答，讓回答以特定資料為主要依據。

02

R、A、G 是一條資料流

03:51

R（Retrieval）負責檢索；A（Augmented）把找到的內容與問題組合；G（Generation）根據這些內容生成答案。影片用「先查資料再回答」概括這個流程。

在實作視角中，R 又可分為先整理書架（資料準備）與再找書（查詢時檢索）。

03

資料清洗、切塊與 metadata 是 R 的基礎

04:52

清洗的目標是提高資訊密度與確保語意獨立：去除轉檔雜訊、寒暄與無意義口語，並補足代名詞、說話者和問答脈絡。影片提到可先用確定性的腳本做物理清理，再以較便宜的小模型做語意整理。

切塊時，固定字數方法易於控制成本，但可能把一句話或問答切斷；若資料有標題或問答結構，依自然結構切塊可讓單一 chunk 保有完整語境。

每個 chunk 也要有 metadata，例如年份、來源或權限標籤，以支援條件過濾與存取控制。

04

混合搜尋同時處理精確名詞與概念相似性

11:07

關鍵字搜尋擅長特定人名、公司代號和專有名詞；語意搜尋用 embedding 把文字轉成向量，適合找到字面不同但意思相近的內容。

影片建議將兩者並行作為 hybrid search，先取得候選 chunk；此時仍只是初篩，尚未直接交給模型作答。

05

A 階段把候選資料濃縮成可用的小抄

14:31

初步檢索回來的候選中可能混有半相關內容。影片將 reranking 放在 A 的理解架構裡：讓較仔細的模型逐一比對問題與候選資料，將真正有用的內容排到前面。

之後挑選少量高相關 chunk，連同 metadata、問題及「只能依資料回答，資料沒有就說不知道」等指示，組成最終提示。

06

G 階段與排錯順序

16:06

G 是把小抄交給語言模型生成答案。影片指出，知識庫問答不一定需要最昂貴的模型；若回答不一致或過度延伸，可先降低 temperature。

若答案錯誤，先檢查資料是否切壞或辨識錯，再檢查檢索是否漏掉正確資料、reranking 是否未把它送進前幾名，最後才檢查 system prompt 與模型本身。

RAG 的核心，是在有限的上下文裡，把最正確、最有密度的資料交到 AI 眼前。
