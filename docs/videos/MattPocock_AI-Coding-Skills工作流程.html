01

安裝與初始設定

0:54

Ask Matt — 內建知識庫 skill

入門指引
03

主流程：Grill with Docs → Spec → Tickets → Implement

8:23

完整工作流程分為四個階段：

① Grill with Docs（需求訪談）：以對話方式釐清你的想法。你只需要給一個模糊的方向（例如「我想移除大部分內部工具」），skill 會自動探索 codebase、提出追問，直到雙方達成 shared understanding。過程中會將學到的資訊記錄到 context.md 和 ADR。

② To Spec（規格文件）：將 grill 階段的所有討論（可能高達 46K tokens）壓縮成一份結構化規格文件，包含 problem statement、solution、user stories、implementation decisions、testing decisions。這份 spec 是整個 multi-ticket sprint 的「終點描述」。

③ To Tickets（任務拆分）：將 spec 拆分為多個 ticket，每個 ticket 的大小設計為單一 context window / smart zone（Matt 建議保持在 ~140K tokens 以下，超過會出現 attention degradation）。每個 ticket 就是一個獨立 session 的工作量。

④ Implement + Code Review（實作與審查）：依 ticket 逐一實作，每個 ticket 完成後清空 context 再進行下一個。Implement skill 內建 code review，會用 sub-agent 比對實作結果與原始 spec，以及 coding standards。Matt 強調用 sub-agent 做 review 比主 agent 更客觀——主 agent 剛寫完程式碼容易自我感覺良好。

核心流程
04

Context Window 管理心法

10:38

Matt 將 context window 分為「smart zone」（~140K tokens 以下）和「退化區」（超過 140K）。在 smart zone 內 LLM 表現最佳；超過後容易出現 hallucination 和注意力衰退。

實務策略：每個 ticket 完成後就清空 context，不要在同一個 session 連續做多個 ticket。如果工作量大到需要多個 session，就走 spec → tickets 路線，不要硬塞進單一 context window。

最佳實踐
05

Skills 的設計哲學

4:01

Matt 的 skills 與其他 skills repo 的關鍵差異：大部分是 user-invoked（使用者主動呼叫），而非自動注入 context。這讓 skills 的 context 佔用極低——即使安裝了全部 38 個 skills，也只佔用約 660 tokens。

Skills 支援多種 agent harness（Claude Code、Cursor、Codex 等）和多種 issue tracker（GitHub、Jira、Linear、local markdown），只需在 setup 時告知 agent 即可自動配置。

設計理念

The main flow: align before you start, create spec and tickets for multi-session work, implement with built-in code review. Keep each ticket within a single smart zone, clear context between tickets, and use sub-agents for better code review.
