Claude Code Hooks 完整教學：設定架構、Event / Matcher / Handler 與兩個實戰案例

📺 Gary Chen⏱ 19:57🗓 2026-08-16🌐 zh-Hant🔗 https://youtu.be/rLNGSDYkK-w?si=UJNe-qqwCCfnf013

這支影片把 Claude Code Hooks 定位成比 CLAUDE.md 更強制、穩定的自動化機制：CLAUDE.md 像提醒紙條，仍依賴模型自己記得；Hook 則由軟體在固定時機強制觸發。影片依序說明 Hook 設定檔的三層架構 Event、Matcher、Handler，整理常用 Event 與五種 Handler 類型，並用兩個案例示範：提交前阻擋 .env / API 金鑰，以及文章完成前啟動 Humanizer Gate 檢查 AI 腔。最後比較 Claude Code 與 Codex 的 Hook 差異，提醒不要直接複製設定，而要用「何時啟動、啟動後做什麼」重新描述需求。

01

Hook 是把「固定時機」與「強制動作」綁在一起

0:00

影片先用 CLAUDE.md 當對照：CLAUDE.md 每次工作時會被讀取，適合放專案資訊或個人偏好，但它本質上仍像給 AI 的提醒紙條，是否遵守仍依賴模型自己判斷。

Hook 的差別是 deterministic：由 Claude Code 軟體在背後掌控，設定的時間點一到就強制介入，不是靠模型自己記得。影片用便利商店自動門比喻，只要有人走到感應區，門就必定打開。

因此，一次性任務直接在對話講；專案通用規則寫進 CLAUDE.md；但只要是固定時機一到就絕對要執行、而且不想承擔 AI 忘記風險的動作，就適合做成 Hook。

02

Hook 設定檔的三層架構：Event、Matcher、Handler

2:23

影片說明 Hook 設定通常是 JSON，會放在專案資料夾的 `.claude/settings.json`。不需要死背格式，先理解三層分工即可。

第一層是 Event，決定 Hook 什麼時候啟動。例子是語法檢查使用 `PostToolUse`，也就是 Claude 剛調用完工具時觸發。

第二層是 Matcher，負責從 Claude 可能調用的許多工具中篩出真正要攔截的操作；第三層是 Handler，在條件符合後決定要叫哪個腳本、服務或 AI 出來做事。

03

常用 Event：從啟動、工具使用、結束到特殊狀況

4:00

Claude Code 目前有 31 種 Event，影片建議先用工作階段分類來理解。對話開始或恢復時有 `SessionStart`，可用來強制載入 Skill；送出 prompt 時有 `UserPromptSubmit`，可在對話前先撈出相關記憶。

工具使用前後是安全防呆與驗收的關鍵：`PreToolUse` 在工具即將執行前觸發，適合擋危險 Git 指令；`PostToolUse` 在工具成功執行後觸發，適合快速驗收，例如 UI 檔案改完後掃描圖片連結或色彩對比。

工作結束或特殊狀況包含 `Stop`、`Notification`、`SubagentStart` / `SubagentStop`、`PreCompact`。影片特別提醒第一次接觸可先記住四個：`SessionStart`、`PreToolUse`、`PostToolUse`、`Stop`。

04

Matcher 與 Handler 決定 Hook 會不會吵、做得夠不夠準

9:00

Matcher 的工作是從所有可能動作裡挑出 Hook 真正要處理的目標。影片例子是只關心 `Edit` 和 `Write`，甚至可以再加 if 條件，只檢查副檔名是 `.ts` 的程式碼。

Handler 決定條件符合後實際做什麼。影片列出五種類型：`command`、`http`、`mcp_tool`、`prompt`、`agent`。`command` 最常見，適合跑本機指令或腳本；`http` 可把錯誤送 Slack；`mcp_tool` 可從 Jira 等 MCP 工具抓任務。

`prompt` 與 `agent` 都會呼叫另一個 AI 判斷，但 `prompt` 只根據事件資料回答；`agent` 會啟動 subagent，能讀檔、搜尋程式碼或跑測試後再回傳驗收結果。

05

實戰一：提交前擋下 .env 與 API 金鑰

11:55

建立 Hook 時，影片建議先講清楚兩件事：它要在什麼時候啟動，以及啟動後要做什麼。第一個案例的需求是：當 Claude 準備執行 Git commit 時，先檢查提交內容是否包含 `.env` 檔案或疑似 API 金鑰。

Claude 建立出的 Hook 使用 `PreToolUse`，Matcher 鎖定 `Bash`，放在全域 `.claude/settings.json`，所以任何專案只要 Claude 準備執行 Git commit 都會經過這道檢查。

Handler 會叫起一支 `Git Commit Secret Guard` 檢查程式；如果與提交無關就安靜結束，若發現 `.env`、私鑰、憑證或疑似 API 金鑰，就阻擋提交並指出問題檔案。影片也示範敏感資料會擋下、移除後可正常提交。

06

實戰二：用 Humanizer Gate 阻止 AI 腔文章直接結束

14:11

第二個案例處理的是比較質化的判斷：Claude 寫出的文章資訊可能正確，但讀起來有 AI 腔。影片示範的需求是：每當 Claude 寫完 Blog 文章、準備結束工作時，啟動一個 Agent 讀取文章，呼叫 Humanizer Skill 檢查。

這個 Hook 使用 `Stop` Event；當 Claude 準備結束工作時，Hook 先確認這次是否有修改 Blog 文章，再由 `Humanizer Gate` 找出尚未通過檢查的文章，要求 Claude 開 Agent 審查。

如果 Agent 找出 AI 寫作痕跡，會把問題段落與原因交回給 Claude，請它繼續修改；通過後這次工作才結束。文章若後來又被修改，原本的通過紀錄會失效，下次結束前重新檢查。

07

長期使用 Hook 前，要檢查範圍與退出條件

15:40

影片提醒，請 Claude 建立第一版 Hook 時，只要先說清楚「何時啟動」與「啟動後做什麼」即可；但要長期穩定使用，還要檢查觸發範圍是否精確。

範圍太大會讓 Hook 在無關操作中被叫起，浪費時間並打斷工作。影片的 Git 案例先用 Matcher 鎖定 `Bash`，再由檢查程式判斷是否真的是 Git commit；無關指令就安靜結束。

Stop Hook 還必須有明確的通過條件與退出條件，否則可能一直退回、修改、再檢查。Humanizer Gate 會記錄目前版本是否通過；如果連續三輪仍未通過，就停止退回，交給人工確認。

08

Codex 可沿用判斷方式，但不能直接複製 Claude Code 設定

17:44

影片結尾指出，Codex 用戶也可以沿用同一套需求表達方式：先說清楚什麼時候啟動，以及啟動後要做什麼。

但 Claude Code 與 Codex 支援的 Event 和 Handler 不完全相同。影片提到 Claude Code 有 31 種 Event，Codex 有 11 種；`PreToolUse` 與 `Stop` 兩邊都有，因此 `.env` 檢查和 Humanizer Gate 的基本做法可以搬過去。

Handler 差異更大：Claude Code 支援 `command`、`http`、`mcp_tool`、`prompt`、`agent`，Codex 目前真正會執行的是 `command`。所以最簡單的做法不是複製設定，而是把要解決的問題直接告訴 Codex，請它依目前支援格式重新建立。
